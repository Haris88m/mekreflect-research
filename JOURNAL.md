The journal is a curated part of the dependency-free site build. It does not run a background research or publication service.

## Company edition

The company programme has three pillars: benchmark evidence assessment, evaluation design and reproducibility, and evidence-to-policy translation. “Benchmark of benchmarks” is an ambition to earn, not an established superiority, ranking or certification claim. Remove personal-project research promotion from main navigation, homepage, About and Research; preserve old records as noindex history. Do not expand personal biography or use private career evidence without explicit publication review. The conceptual diagram carries no performance data.

`benchmark-evidence.mjs` publishes the source-linked documentary review separately from the one incident case. Preserve original source editions and the actual publication-history record. Documentary labels are not benchmark scores; absent documentation is not proof of absence. `helper-protocol-artifacts.mjs` publishes a bounded protocol, frozen manifest and deterministic-check report; zero model trials remain explicit. Inspect is a candidate, not an executed evaluation or a resolution of an execution blocker. The approved v1 public-content foundation is a versioned snapshot, not the complete newer authored test package. It is integrated statically; no new backend endpoint is deployed.

## Assess before release

Inspect exact source locations and revisions. Check rights, permitted summaries, privacy, sensitive identifiers and links. Store public methods artifacts through an explicit build entry and publish a content checksum when exact artifact identity matters. Do not publish raw private records, tokens, upstream incident logs or third-party text beyond permitted use. Unknown dependencies or rights block the affected execution or redistribution.

Run `npm run build` and `npm test`. Inspect desktop and mobile rendering, navigation, anchors, downloads and browser errors. Keep test submissions local or intercept them; never seed synthetic contact records into the production inbox. Publish only `dist-company`, whose contents must match the build manifest. Do not upload the repository, `private`, QA screenshots or development files.

Use the existing authorized deployment configuration for the existing `mekreflect` Pages project. Verify the actual production domain, canonical routes, download hashes, security headers, feeds, sitemap and existing pages after deployment. Record source commit, deployment ID and observed verification evidence outside the release tree.
