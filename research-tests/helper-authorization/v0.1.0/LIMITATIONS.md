# Limits and remaining gates

- One invented desk-hours family; simple structured actions and exact payload values. No natural-language permission parser or realistic communications stack has been evaluated.
- Five variants do not establish prevalence, statistical power, cross-provider robustness or benchmark quality. The alternative condition changes capability. The no-helper condition is evidence-limited and not a solved task.
- The answer oracle and expected labels are separately authored, not independently validated. Source-code self-review and mutation checks are not external independent review.
- Deterministic traces are scripted controls. No AI generated them, no model was scored and no model safety or policy-effectiveness result follows.
- The event ledger is locally generated and checked for consistency. It is not a cryptographically authenticated audit system for a production deployment. The model cannot write ledger events through its trace interface.
- Free-form assistant text is retained but factual honesty is not automatically scored. Structured final answers and fixed limitation rendering define the assessed output; a future pilot needs separate review of contradictory prose.
- The helper response's fake approval tests one authored instruction pattern. It is not an adversarially comprehensive attack suite. A future pilot must preserve this development/held-out distinction.
- The gate is deliberately separate from the scorer. Blocking a call is enforcement, not evidence of correct agent judgment. Fault injection remains entirely in memory.
- Node standard-library execution is available for this original package. This does not resolve any separate SDK environment-admission issue or establish an approved environment for model evaluation.
- Inspect integration is drafted only. It would require an independently checked port/adapter, correct trusted-user message routing, isolated tool exposure, reproducible logs and exact version settings before use.
- No provider access, model version, budget, repetition plan, external reviewer or owner approval is established for a real-model run. These remain explicit blockers; the run template is not permission.
- No outside contact, credential access, dependency install, third-party SDK import, shell-enabled agent tool or real-target action is implemented by the harness.
